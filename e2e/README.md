# 主流程冒烟(Playwright)

父任务 MTM-274 的**五个关键场景**,一条命令从头走一遍。单测按住的是零件,这里按住的是
「今天早上打开指挥舱,该看清的都看得清、该点的都点得动」。

## 跑起来

```bash
cd e2e
npm install
npm run install-browser   # 只有第一次要:下载 chromium(约 115MB)
npm run smoke
```

不用先起服务 —— 冒烟会自己在仓库根跑 `npm start`;已经起着就直接复用那一个。
报告在 `e2e/report/`(`npx playwright show-report report`),失败时的截图和 trace 在
`e2e/test-results/`。两个目录都已 gitignore。

想打别的地址:`COCKPIT_URL=http://127.0.0.1:4791 npm run smoke`。

## 覆盖到哪

| 场景 | 断言的是 |
|---|---|
| 1 早上打开 | 默认就是**真数据**(不是演示数据)、13 张角色卡、告警组与计数条同屏、首屏 < 3 秒 |
| 2 看谁卡住 | 点卡进详情 → 技能栏 / 装备栏 / 战绩都在;喊话弹窗两段式确认 + 警示语 |
| 3 舱内派活 | 目标空着不许提交、角色可选、确认页写明「真实创建 issue」「消耗用量」 |
| 4 战役地图 | 战役列表 → 关卡按 stage 排布 → 点节点出侧栏详情 |
| 5 战斗回放 | 接力链按时间轴展开,「本棒」标记在 |
| 出错与空态 | 角色/战役不存在给人话 + 回主视图的路;BFF 断了给黄条**且不清屏** |
| 接口边界 | 乱填 id 是 400/404 不是 500;白名单外的写操作一律当不存在;界面与接口同源同端口 |

## 两条底线

**不做真实写操作。** 派活和喊话都会真的建 issue、真的唤醒智能体、真的烧用量。
冒烟走到两段式确认页的最后一步为止就取消 —— 除了最后那一次 POST,整条链路都覆盖到了。
那一次 POST 由人手按,并在对应 issue 里留痕。

**不写死今天的数据。** 谁在打怪、有几个项目每小时都在变。断言一律先问 `/api/roster`
再挑对象;挑不到就 `test.skip` 并说清为什么(例如「此刻没有人在阵地上,喊话没有落点」),
不假装通过。所以偶尔看到 skip 是正常的,看到 fail 才是出事了。

## 红了先看一眼是不是 harness 自己崩了

`retries` 刻意设成 0 —— 冒烟红了就该有人去看,自动重跑会把真的偶发盖掉。

代价是极少数时候会撞上 Playwright 自己的崩溃。MTM-279 收口时在干净克隆上撞到过一次
`worker process exited unexpectedly (code=3221226505)`(Windows 的 STATUS_STACK_BUFFER_OVERRUN,
崩的是 playwright 的 worker 进程,不是指挥舱),同一条用例接着重复跑 5 次、整套接着跑 3 次都没再现。
**分辨方法**:报错里写的是 worker 崩了、用例耗时 0ms、没有断言失败信息 —— 那就是 harness,
直接重跑;有断言失败信息的才是产品的问题。

## 加新场景时

文件后缀必须是 **`.spec.ts`**。仓库根的 `npm test` 是裸 `node --test` 全仓库自动发现,
它按名字认 `*.test.ts` —— 撞上就会被 node 抢着跑然后当场红。规则详见仓库根 README。
