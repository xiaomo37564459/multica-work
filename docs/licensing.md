# 开源协议说明

本项目使用 **Apache License 2.0**（下称 Apache-2.0）。

- 法律原文：仓库根目录的 [`LICENSE`](../LICENSE)
- 版权与第三方声明：仓库根目录的 [`NOTICE`](../NOTICE)
- SPDX 标识：`Apache-2.0`（`package.json` 的 `license` 字段）

这份文档是**人话版说明**，帮你搞清楚「别人能拿它做什么、必须做什么、我不能拦什么」。
两者冲突时以 `LICENSE` 原文为准。

## 一句话

**别人可以自由使用、修改、卖你的东西，包括商用，不用给你钱；
唯一的主要条件是保留你的版权声明、附上协议全文、并说明改了什么。**

这就是「宽松许可」（permissive license）的意思：你放弃了控制权，保留了署名权。

## 别人可以做什么（不用问你）

| 可以 | 说明 |
|---|---|
| ✅ 商用 | 拿去做内部工具、做成产品卖钱，都不用付费、不用分成 |
| ✅ 修改 | 随便改代码，改成什么样都行 |
| ✅ 再分发 | 原样或改过之后发给别人 |
| ✅ 闭源 | 改完之后**不必**开源自己的改动（这是它和 GPL 最大的区别） |
| ✅ 用在专利上 | 见下面「专利授权」一节 —— 这是 Apache-2.0 比 MIT 强的地方 |

## 别人必须做什么（这几条是硬条件）

1. **保留版权声明与协议全文** —— 分发时要带上 `LICENSE` 和 `NOTICE`
2. **写明改了什么** —— 改过的地方要标注（法律第 4 条 b 款）
3. **带上 `NOTICE` 内容** —— 如果分发的是改过的版本，`NOTICE` 里原有的声明不能删
4. **不能拿你的名义背书** —— 不许暗示「原作者认可我的产品」

**违反了会怎样**：授权自动终止（第 4 条）。但如果你在收到通知后 30 天内改正，
授权自动恢复 —— 这是 Apache-2.0 刻意留的缓冲，不是给赖账用的。

## 别人不能做什么

- ❌ **用你的商标** —— 第 6 条明确：本协议**不授予任何商标权**。
  「AetherLab」这个名字、logo 都还是你的，别人不能拿去当自己的产品名。
- ❌ **拿你当挡箭牌** —— 没有担保（第 7 条）。软件按「原样」提供，
  出了任何问题你都不负责。这条对你是保护。
- ❌ **无限追责** —— 赔偿责任有限（第 8 条）。
- ❌ **反过来告你侵权** —— 如果别人对你发起专利诉讼，指控本项目侵犯专利，
  那么他基于本协议获得的专利授权自动终止（第 3 条）。这条是防「吃了饭砸锅」的。

## 专利授权（Apache-2.0 最关键的一条）

第 3 条：**每个贡献者都自动授予使用者一项专利许可**，覆盖他贡献内容中必然涉及的专利。

**为什么这条值钱**：MIT 协议对专利只字未提，理论上可能出现
「代码免费用，但其中用到的技术回头告你侵权」这种坑。Apache-2.0 把这条路堵上了。

对开源共创的项目，**这条是最实际的选择理由** —— 大家敢用、敢贡献，
因为知道不会被贡献者回头用专利咬一口。

## 你（版权方）要清楚的三件事

### 1. 开源不等于放弃版权

**版权还是你的**（Copyright 2026 xuhongwei）。你只是**授权**别人使用，
授权不等于转让。别人分发你的代码时，必须保留你的版权声明。

### 2. 你可以继续用自己的代码做任何事

包括闭源、商业化、另发一个许可版本 —— 因为版权在你手上。

### 3. ⚠️ 一旦别人贡献了代码，你就不再能单方面换协议

**这条最重要，直接关系到「共创」。**

现状：整个仓库的版权目前只有你一个人，所以你现在想换协议随时能换。

但如果别人提交了代码并被合并，**那部分代码的版权就属于他**。
之后你想把所有代码从 Apache-2.0 换成别的协议（比如换成更严的协议、
或者做商业双授权），**必须征得每一位贡献者的同意** —— 少一个都换不了。

**这就是为什么大项目都要签 CLA。** 你的处境要先想清楚：

| 方案 | 好处 | 代价 |
|---|---|---|
| **A. 什么都不加**（Apache-2.0 第 5 条自动兜底） | 门槛最低，谁都能提 PR。第 5 条规定：贡献默认按同一协议授权进来 | 你永久失去「整体换协议 / 商业双授权」的自由 |
| **B. 加 DCO**（贡献者在提交里签名 `Signed-off-by`） | 门槛很低（一条 git 参数），能证明「他有权贡献这段代码」 | 同样**不能**让你换协议；只解决「代码来路是否干净」 |
| **C. 加 CLA**（贡献者签一份授权协议） | 保留你换协议、做商业双授权的权利 —— 公司主导的开源项目基本都这么做 | 门槛最高，个人贡献者会觉得麻烦，可能劝退一部分人 |
| **D. 接受「不换协议」这个事实**，专心做共创 | 最省事，社区最友好 | 以后想改协议或做商业授权，要回头找所有贡献者 |

**我的建议：先定 D（什么都不加），真要商业双授权了再升级到 C。**
理由：项目现在是个人开源、目标是「大家一起来创」，加 CLA 的劝退成本
远大于它现在能带来的收益；而 Apache-2.0 本身已经给了商业使用的自由
（别人可以商用，你也不受影响），双授权的动机不强。

**⚠️ 但这是可以事后改主意的决定，反过来很难** ——
所以现在就把话说清楚：**如果你将来可能想商业双授权，现在就该上 CLA**，
等几十个人贡献过之后再补，基本就补不动了。

## 怎么用这份协议（给使用者）

```bash
git clone https://github.com/xiaomo37564459/multica-work.git
cd multica-work
npm start
```

克隆、修改、分发都不需要另行申请。**唯一要做的**：
在你分发的东西里带上 `LICENSE` 和 `NOTICE`，并说明你改了哪里。

## 怎么贡献（给想一起做的人）

1. 先读 [`docs/customize.md`](customize.md) —— 讲清了哪些该改、哪些千万别改
2. 起分支、提 PR，讲清「解决什么问题」和「怎么验的」
3. **你贡献的代码默认按 Apache-2.0 授权**（协议第 5 条）。
   换句话说：**你提 PR，就等于同意大家按 Apache-2.0 使用你的贡献。**
4. 别提交别人的代码而不注明来源 —— 来路不清的代码会让整个项目有法律风险

## 常见问题

**Q：我能用它做商业产品卖钱吗？**
A：能。不用付费、不用告诉我、不用分成。只要保留版权声明和协议全文。

**Q：我改完了必须开源吗？**
A：不必。Apache-2.0 不要求你开源自己的改动（要求开源的是 GPL 那一类）。
但改了的地方要标注。

**Q：我能把名字改成别的吗？**
A：代码随便改。但**不能**用「AetherLab」做你自己的产品名 ——
协议不授予商标权（第 6 条）。改个名再发是没问题的。

**Q：能用在 GPL 项目里吗？**
A：能用在 GPLv3 项目里（协议兼容）；**不能**用在「只认 GPLv2」的项目里
（两者不兼容，这是公认的已知限制）。

**Q：作者不维护了怎么办？**
A：协议已经授予你永久、不可撤销的权利（前提是你没违反协议）。
作者撒手不管，不影响你继续使用和分发。

**Q：需要我保留 `NOTICE` 文件吗？**
A：要。分发时 `NOTICE` 里的声明不能删。
