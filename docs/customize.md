# 改成你自己的队伍（开源共创指南）

> **这份文档解决一个问题**：你克隆下来，看到的是 13 个叫「沈执」「苏绘」的角色 ——
> 那是作者 heory 的团队。**换到你自己的 workspace，怎么让指挥舱显示你自己的智能体？**
>
> 答案分两半，先说要改什么，再说**哪些绝对不用改**（那是这个项目的设计价值所在）。

## 一、先说结论：角色是「半写死」的

这不是含糊其辞，是有明确分工的：

| 层 | 数据从哪来 | 换 workspace 后 |
|---|---|---|
| **数据层**（谁在忙、打什么怪、战绩、接力链） | 真跑 `multica` 命令，**自动读你的 workspace** | ✅ **什么都不用改，自动就是你的队伍** |
| **立绘层**（每个人的像素小人长什么样） | `pixel/sprites/roster.js` 里的名册，**写死的 13 条** | ⚠️ 需要你补自己的角色 |
| **身份色**（卡片顶条的颜色） | `pixel/tokens.css` 里的 `--pc-unit-*` | ⚠️ 跟名册一起补 |

**为什么立绘要写死**：像素小人不是一张图片，是**代码画出来的**（共用身体 + 头饰 / 服装 / 道具
三个可变位置）。要保证 13 个人「一眼看出是同一套画风」，就必须有一个统一的骨架和调色机制 ——
这部分是**刻意的设计约束**，不是偷懒。详见 `pixel/README.md`。

**好消息**：**没配立绘的角色不会崩，也不会消失。**
`web/src/components/bits.tsx` 里有兜底逻辑 —— 名册里查不到的角色，
自动退回它的 `avatar_url`（emoji / 图片 / 未知占位三种形态都认）。
所以你换 workspace 之后，**页面立刻就能跑，只是新角色显示 emoji 而不是像素小人**。

## 二、换成你自己的队伍：三步

### 第 1 步 · 拿到你自己的人名单

```bash
multica agent list --output json
```

把每个人的 `id` / `name` / `description` 记下来。名册里要用的就是这三样。

### 第 2 步 · 往名册里加记录

打开 `pixel/sprites/roster.js`，照现有格式加一条：

```js
{
  key: 'zhang',              // 姓氏拼音小写，短、不重复
  name: '张工',              // 显示名
  title: '后端',              // 职业定位
  agentId: '从上面那条命令拿',  // ← 立绘和真实数据对上号的钥匙
  unit: '#4f7fe0',           // 身份色，只给一个，暗部亮部自动推导
  head: 'slick',             // 从 parts.js 的 HEADS 里挑，或自己加一个
  hair: HAIR.black,
  skin: SKIN.mid,
  outfit: 'coat',            // OUTFITS
  prop: 'setsquare',         // PROPS
  propColor: '#8fd8ea',      // 道具色，必须和衣服拉开，否则糊成一坨
  accent: '#e8762c',         // 领带 / 帽子这类小面积配色
  note: '一句话说清他长什么样',
},
```

**四个状态、图集位置、头像片、失败态摔道具全部自动生成**，不用再画第二遍。

`head` / `outfit` / `prop` 想换成新的，就去 `pixel/sprites/parts.js` 照抄旁边函数的签名加一个。

### 第 3 步 · 同步身份色

把 `unit` 的颜色加进 `pixel/tokens.css` 的 `--pc-unit-<key>` —— 卡片顶条用的是这个值，
不同步的话立绘和卡片颜色会对不上。

### 想清空作者的人、从零开始？

把 `roster.js` 里的 `ROSTER` 数组清成 `[]` 就行，页面会全员走 emoji 兜底。
编辑器里删之前建议先看一眼 `pixel/README.md` 的「为什么 13 个人看起来是一套的」——
那四条机制（统一描边、禁止手写明暗、共用身体、下半身同色）是你要保留的东西。

> **顺带一提**：`web/src/mock/world.ts` 里还有一份 13 人的 mock 演示数据。
> 那是给**开发界面时**用的（不连真后端就能调样式），跑正式服务不影响。
> 你想让开发服的演示数据也换成自己的队伍，改那个文件即可。

## 三、哪些千万别改（这才是这个项目的价值）

**这部分比上面重要。** 换掉角色名不叫共创，**保留下面这套骨架才叫**。

| 要保留的东西 | 在哪 | 为什么 |
|---|---|---|
| **七态状态判定规则** | `src/aggregate/battle-state.ts` | 「谁卡住」的判定顺序本身就是设计。尤其**第七态 `waiting`（待接力）** —— 派单的人不算卡住也不算空闲，少了这一态，「卡住」这盏灯就有已知误报 |
| **游戏映射** | `docs/design-overview.md` | 任务=战斗、issue=关卡、project=剧情、血缘=接力。**换个名字这套映射依然成立** |
| **三条主目标的排序** | 同上 | 看得见 > 能操控 > 游戏代入感。冲突时的取舍依据 |
| **数据契约与文档** | `src/contract/types.ts` + `docs/` | 字段名、空值约定、未知枚举降级 —— 换成哪个 workspace 都是这套 |
| **安全边界** | `docs/security.md` | 写操作白名单只有两条、凭据绝不落仓库、绝不暴露公网。**这几条和团队规模无关，谁跑都得守** |
| **分档轮询** | `docs/polling.md` | `agent tasks` 没有分页、一次返回全部历史 —— 这是平台的硬约束，**人越多越要守** |

## 四、人比 13 个多或者少，会怎样？

**运行时不会因为人数变化而出错**，但有几处会显得别扭，提前告诉你：

| 情况 | 表现 | 怎么办 |
|---|---|---|
| **人更多**（比如 30 个） | ① 主视图一屏放不下，要滚动<br>② 冷档轮询更慢（`agent tasks` 是每人一次调用）<br>③ `agent tasks` 无分页，历史越长越慢 | 调 `COCKPIT_WARM_MS` / `COCKPIT_SWEEP_MS`；真实瓶颈和实测数字见 `docs/polling.md` |
| **人更少**（比如 3 个） | 一切正常，只是页面显得空 | 不用管 |
| **有角色没配立绘** | 显示 emoji 头像，不崩 | 照第二节补名册即可 |

⚠️ **一个真实的坑**：测试里有几处把「13」写死了
（`pixel/tests/sprites.test.js`、`web/src/mock/store.test.tsx`、`web/src/screens/screens.test.tsx`）。
你加了角色之后 `npm test` 会红 —— **这是测试在提醒你去更新它，不是产品坏了**。
改数字即可，别把测试删掉。

> 如果你只是想把指挥舱跑起来看自己的队伍，**这一节可以完全不管**：
> 不配立绘、不动测试，`npm start` 照样能用。

## 五、设计理念怎么带走

如果你想把「这套玩法」用到自己的项目上（哪怕不用这份代码），带走这三样：

1. **先找真数据，再定游戏映射**。
   这个项目的映射表能成立，是因为**每一项都能指到一条真跑通的命令**。
   先列数据、再起名，别反过来硬套皮肤 —— 硬套的皮肤活不过一周。

2. **状态灯宁缺毋滥**。
   七种状态里有两种（`unknown` / `waiting`）是专门为「不许猜」加的。
   状态灯撒谎一次，整屏就没人信了 —— 这是这类工具的死穴。

3. **天花板要提前写下来**。
   「平台只给任务开始/结束，不给中间过程」这条天花板，
   决定了二期才做「战斗直播」。**提前写清做不到什么，比承诺做得到什么更重要。**
   （示例见 `docs/design-overview.md` 第八节）

## 六、还有哪些是写死的（诚实清单）

一次性说清，免得你踩到：

| 位置 | 写死了什么 | 影响 |
|---|---|---|
| `pixel/sprites/roster.js` | 13 个角色的人设与配色 | 见第二节，照着加 |
| `pixel/tokens.css` | 13 个身份色 token | 同上 |
| `web/src/mock/world.ts` | 13 人的 mock 演示剧本 | 只影响开发服，不影响正式服务 |
| `docs/screenshots/` | 作者 workspace 的截图 | **你换了队伍之后截图就过时了，可以删掉重截** |
| 测试里的 `13` | 见第四节 | 改数字 |
| 底部状态栏的 `/src/contract/types.ts` 等提示 | 指路文案 | 与数据无关 |

**没有写死的**（自动就是你的数据）：所有人名、职业、技能、任务、issue、项目、血缘链、token 用量。

## 七、想要截图？

`docs/screenshots/` 里那八张图是照着这份文档的说明抓的。你自己抓一份：

```bash
npm start                        # 先把指挥舱跑起来
node pixel/tools/serve.js        # 另开一个终端:像素样张(5178)
node e2e/screenshots.mjs         # 再开一个:抓六张图(需要 e2e 装过依赖)
```

脚本会把六到八张图写到 `docs/screenshots/`。

### 截图里为什么会有口令风险（已处理）

回放页和角色详情页展示的是任务**交付原文**，里面可能夹着口令、密钥这类东西
（实测确实撞到过：某条链的正文里写着另一个项目的默认后台口令）。
而本仓库是 **PUBLIC** 的 —— 直接提交等于把口令公开。

所以抓图脚本内置了敏感模式过滤（`123456` / `password` / `api_key` / `Bearer` / `gho_` /
`-----BEGIN` 等），**命中就跳过那条链、换一条**，宁可截图短一点也不提交。
过滤掉东西时输出会打印一行「跳过了 N 条含口令/密钥样式的链」。

要单独在文档里引用某张图：

```markdown
![指挥舱主视图](docs/screenshots/01-roster.png)
```
